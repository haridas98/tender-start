# TenderStart: UX/UI план нового продукта

## 1. Главная идея интерфейса

TenderStart должен ощущаться не как каталог и не как таблица тендеров, а как рабочий центр сделки.

Главный вопрос интерфейса:

> "Как купить или продать нужное сырье выгоднее, надежнее и быстрее?"

Базовая цепочка:

`вещество -> требования -> подходящие производители -> цена -> логистика -> документы -> риски -> запрос предложения -> сделка`

## 2. Главные пользователи

### ИП / участник рынка

Задача: найти возможность заработать.

Главный экран для него:
- "Что сейчас можно купить и кому продать?"
- маржа;
- доступные поставщики;
- потенциальные покупатели;
- кнопка "Собрать сделку".

### Закупщик завода

Задача: найти поставщика сырья.

Главный экран:
- поиск вещества;
- нужные характеристики;
- список подходящих производителей;
- сравнение цены до склада;
- документы;
- риски;
- RFQ-запрос.

### Производитель

Задача: найти покупателей.

Главный экран:
- кто покупает его вещество;
- какие требования на рынке;
- где есть тендеры;
- какие цены проходят;
- куда можно экспортировать.

### Логист / брокер

Задача: получить лиды на перевозку.

Главный экран:
- активные маршруты;
- химический класс груза;
- объем;
- порт/станция отправки;
- порт/станция назначения;
- срок;
- контакт сделки.

### Аналитик / регион / государство

Задача: увидеть зависимости экономики.

Главный экран:
- карта импорта/экспорта;
- уязвимые вещества;
- импортозамещение;
- дублирующиеся цепочки;
- где можно строить производство.

## 3. Информационная архитектура

Главное меню:

1. **Поиск сырья**
2. **Вещества**
3. **Заводы**
4. **Поставщики**
5. **Покупатели**
6. **Сделки**
7. **Карта**
8. **Источники**

Второстепенное:

- RFQ-запросы;
- документы;
- контакты;
- логистика;
- аналитика;
- избранное.

## 4. Главный сценарий: "Мне нужна сера"

### Шаг 1. Поиск

Пользователь вводит: "сера".

Система показывает:
- варианты вещества;
- CAS;
- HS/ТН ВЭД;
- распространенные марки;
- опасность/класс перевозки;
- где применяется.

### Шаг 2. Уточнение требований

Форма должна быть короткой:

- чистота / концентрация;
- гранулы, порошок, жидкость;
- объем;
- страна/город доставки;
- срок;
- документы;
- бюджет;
- нужна ли отсрочка платежа.

### Шаг 3. Результаты

Не просто список. Нужно 3 вкладки:

1. **Лучшие поставщики**
2. **Самая низкая цена**
3. **Самый надежный вариант**

Каждая карточка:
- производитель или посредник;
- страна;
- цена FOB/EXW;
- цена до склада;
- MOQ;
- мощность;
- документы;
- срок доставки;
- риск;
- уверенность данных;
- кнопка "Запросить КП".

### Шаг 4. Сравнение

Сводная таблица:

- производитель;
- марка;
- характеристики;
- документы;
- цена;
- объем;
- логистика;
- пошлина/НДС;
- итоговая цена до склада;
- риск;
- вывод AI.

### Шаг 5. Сделка

Кнопка:

> "Собрать сделку через TenderStart"

После этого создается deal room:

- покупатель;
- поставщик;
- логист;
- документы;
- переписка;
- КП;
- статус;
- задачи;
- расчет маржи.

## 5. Страница вещества

Страница вещества должна быть главным экраном продукта.

Блоки сверху:

- название;
- CAS;
- HS/ТН ВЭД;
- ОКПД2;
- краткое применение;
- риск перевозки;
- средняя цена;
- динамика цены.

Основные вкладки:

1. **Купить**
   - кто продает;
   - цена;
   - характеристики;
   - документы;
   - доставка.

2. **Продать**
   - кому нужно;
   - какие объемы;
   - какие требования;
   - тендеры;
   - закупщики.

3. **Производители**
   - только заводы;
   - отдельно посредники;
   - мощность;
   - страна;
   - подтверждение производства.

4. **Покупатели**
   - заводы;
   - история закупок;
   - повторяемость;
   - контакты отделов закупки.

5. **Логистика**
   - маршруты;
   - порты;
   - сроки;
   - примерная ставка;
   - обходные маршруты.

6. **Документы**
   - COA;
   - SDS/MSDS;
   - TDS;
   - сертификаты;
   - шаблоны договоров.

7. **Источники**
   - откуда взяты цены;
   - откуда взяты объемы;
   - дата обновления;
   - уровень уверенности.

## 6. Страница завода

Страница завода должна отвечать на 3 вопроса:

1. Что завод производит?
2. Что завод закупает?
3. Как с ним заработать или сэкономить?

Блоки:

- профиль компании;
- продукция;
- сырьевая потребность;
- тендеры;
- история контрактов;
- закупочные контакты;
- требования к поставщикам;
- текущие риски;
- подходящие поставщики для каждой потребности.

## 7. Страница поставщика

Главное: понять, это настоящий производитель или посредник.

Блоки:

- производитель / трейдер / неизвестно;
- страна;
- заводы и мощности;
- вещества;
- марки;
- документы;
- экспортные рынки;
- цены;
- MOQ;
- условия поставки;
- контакт продаж;
- проверки и риски.

## 8. Карта

Карта должна быть не украшением, а инструментом.

Режимы карты:

1. **Производство**
   - где производят вещество.

2. **Спрос**
   - кому оно нужно.

3. **Потоки**
   - откуда куда идет товар.

4. **Логистика**
   - порты, ЖД, автодоставка.

5. **Риски**
   - санкции, нестабильные маршруты, дорогая доставка.

6. **Возможности**
   - где есть арбитраж цены или импортозамещение.

## 9. AI-помощник

AI не должен быть чатиком ради чатиков. Он должен объяснять решение.

Функции:

- "Почему этот поставщик лучше?"
- "Почему этот не подходит?"
- "Какие характеристики критичны?"
- "Что спросить у поставщика?"
- "Составь RFQ."
- "Собери КП для покупателя."
- "Где риск в этой сделке?"
- "Какой обходной маршрут?"

Каждый AI-вывод должен иметь:

- аргументы;
- источники;
- уровень уверенности;
- что нужно проверить вручную.

## 10. Визуальный стиль

Стиль: промышленный, деловой, чистый.

Нельзя:

- куча разноцветных кнопок;
- перегруженные таблицы без смысла;
- декоративные карточки;
- маркетинговый лендинг вместо рабочего продукта.

Нужно:

- строгая сетка;
- светлый фон;
- темная боковая навигация;
- понятные таблицы;
- фиксированная правая AI-панель;
- цвет только для статусов: хорошо, риск, плохо;
- маленькая кнопка "источник" у каждой важной цифры.

## 11. Главный экран будущего MVP

Первый экран:

- большая строка поиска: "Введите вещество, завод или страну";
- быстрые сценарии:
  - "Хочу купить сырье";
  - "Хочу найти покупателя";
  - "Хочу сравнить поставщиков";
  - "Хочу найти импортозамещение";
- блок "Возможности недели";
- блок "Популярные вещества";
- блок "Индия -> РФ";
- блок "Последние найденные потребности";
- карта потоков справа или ниже.

## 12. Приоритет переделки UI

### Этап 1. Новый каркас

- sidebar;
- глобальный поиск;
- роли пользователя;
- страницы вещества, завода, поставщика;
- нормальные slugs.

### Этап 2. Сценарий закупки

- форма "мне нужно сырье";
- подбор поставщиков;
- таблица сравнения;
- расчет landed cost;
- RFQ-кнопка.

### Этап 3. Deal room

- карточка сделки;
- участники;
- документы;
- переписка;
- статус;
- расчет маржи.

### Этап 4. Карта экономики

- карта производителей;
- карта покупателей;
- маршруты;
- риски;
- возможности.

### Этап 5. Источники и доверие

- кнопка "источник";
- дата обновления;
- тип данных;
- уровень уверенности;
- история изменений.

## 13. Главный UX-принцип

Пользователь не должен думать: "Где мне искать?"

Он должен видеть:

> "Вот кто продает. Вот кому нужно. Вот цена. Вот документы. Вот доставка. Вот риск. Вот что делать дальше."
